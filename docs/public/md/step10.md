## 4. README

冒頭の URL の表に `docs.ebook.furusawa.work` を足し、補足を 2 点入れました。

```markdown
> [!NOTE]
> - 学習教材のため、JS は未圧縮・未難読化
> - CI/CD 周りの実装はこれから
```

### JS を圧縮・難読化しない理由

| ファイル | 生 | gzip 後 |
|---|---|---|
| `config.js` | 1,977 B | 1,085 B |
| `library.js` | 5,730 B | 2,255 B |
| `reader.js` | 24,270 B | 8,320 B |
| **合計** | **32 KB** | **11.7 KB** |

- **実際に流れているのは gzip 後の 11.7 KB** で、Cloud CDN がキャッシュします。minify で削れるのは初回の 3〜4 KB 程度です
- **クライアント JS の難読化は保護になりません。** ブラウザ上で動く以上、開発者ツールで整形して読めます。このコードに秘密は含まれていません
- **ビルドツールを入れないことを方針にしています。** minify にはビルド工程が要ります
- **コメント付きの読めるソースが、このリポジトリでは資産です。** 設計の意図をコメントに残してあるので、ブラウザの「ソースを表示」からそのまま読めます

必要になった時点で入れる、という判断にしました。

## 5. docs を本番に出す

GCS には nginx の `autoindex` が無いので、Step.07 で入れた `index.json`（ファイル一覧を静的な JSON にしたもの）を生成してから流しました。

```bash
docker compose run --rm tools php tools/bin/generate-docs-index.php
gcloud storage rsync -r docs/public/ gs://my-project-book-509215-docs/ \
  --cache-control="public, max-age=300"
gcloud storage objects update "gs://my-project-book-509215-docs/md/*.md" \
  --content-type=text/plain
gcloud compute url-maps invalidate-cdn-cache ebook --path "/*"

rm docs/public/index.json
```

**CDN のキャッシュを消します。** docs は `max-age=300` で配っているので、何もしなければ最大 5 分は古い版が見えます。
`?cb=…` のようなクエリを付けても、Cloud CDN のキャッシュキーに含まれないので回避できません。

**最後にローカルの `index.json` を消します。** ビューアは `index.json` があればそちらを優先するので、残したまま新しい Markdown を足すと、ローカルのサイドバーに出なくなります。

この手順は Step.11 で CD に移り、main へのマージで自動で流れるようになります。

## 6. リポジトリを公開する

面接で見てもらうために、リポジトリを公開にしました。公開する前に、**Git の履歴全体**を走査しています。
一度でも履歴に入った秘密情報は、あとからファイルを消しても残るためです。

| 確認 | 結果 |
|---|---|
| `.env` | 履歴に一度も無い。`.env.example` のみで、`APP_KEY=` は空 |
| `*.tfstate` | 履歴に無い（`infra/.gitignore` で除外） |
| SA の鍵・秘密鍵・API キー | 無い（`BEGIN PRIVATE KEY`、`AIza…`、`ya29.`、`AKIA…` を全履歴で検索） |
| DB パスワード | 平文の混入なし。ローカル用の `password` のみで、本番は Secret Manager |

そのうえで、判断が要ったものが 3 つありました。

**管理画面のテストアカウント。** README に載せているのは、本番に実際にログインできる資格情報です。
公開すれば誰でも書籍の編集・削除・画像のアップロードができます。
デモとして触ってもらう価値を取り、**意図して公開**しています。ログイン試行は 5 回でレート制限が掛かるので、総当たりは効きません。

**コミット作者のメールアドレス。** 公開すると誰でも見られます。気にするなら履歴の書き換えが必要で、公開後では手遅れです。

**AI 支援の痕跡。** コミットの `Co-Authored-By` や `backend/CLAUDE.md` が含まれます。隠す必要はなく、
設計判断の根拠を docs に残してあるので、使ったうえで自分で判断していることは伝わる構成になっています。

**GCP のプロジェクト ID やバケット名は公開しても問題ありません。** tfstate バケットは非公開、Cloud SQL は IP 許可リストが空、Cloud Run は LB 経由のみで、
**アクセス制御を IAM に寄せてあるので、名前を知られても入口がありません。**

## ハマりどころ

| 症状 | 原因 |
|---|---|
| README の表が表にならない | `\|---\|---\|` の上にヘッダ行が無い。Markdown の表はヘッダ行と区切り線の 2 行がそろって初めて表になる |
| `<sub>` で囲んだ注意書きの文字が重なる | インライン要素の `<sub>` の中に、番号付きリスト（ブロック要素）を入れていた |
| 注意書きの 2 項目が 1 行につながる | `>` の行を続けて書くと同じ段落に結合される。`-` の箇条書きにする |
| 本番の docs に新しいページが出ない | Cloud CDN が古い `index.json` を返している。`?cb=` では回避できないので無効化する |
| ローカルで新しい Markdown がサイドバーに出ない | デプロイで作った `index.json` がローカルに残っている |

GitHub の Markdown で**複数行の文字を確実に小さくする手段は実質ありません**。`<small>` や `style` 属性はサニタイザで落とされ、`<sub>` は行の高さが親のままです。
README の注意書きは、GitHub の alert 記法（`> [!NOTE]`）で囲んで、本文から一段引いた扱いにしています。
