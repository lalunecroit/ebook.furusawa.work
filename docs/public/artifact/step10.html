足したページ

概要・構成（overview.html）

完成した全体の姿を 1 枚に。中心はホストから見た GCP リソースの相関図で、伝えたいのは 2 点。

6 つのホスト名はすべて同じ IP・同じ LB・同じ証明書を指し、振り分けは URL マップの host_rule だけ。そして cdn バケットに書けるのは ebook-admin だけで、公開 API と管理画面を分けた理由が権限の違いとして見える。

ディレクトリ構成（structure.html）

リポジトリの中身をなぜその形なのかと合わせて。Web から見えるのは public/ の中だけ、ルートを 3 ファイルに分けた理由、config.js がホスト名で接続先を決める理由、index.json をコミットしない理由など。

ビューアの整理

サイドバーを OVERVIEW と PER PR に分け、初めて開いたときは概要を出す。

OVERVIEW
  概要・構成            ← 初期表示
  ディレクトリ構成

PER PR
  ▸ Markdown           ← 既定で閉じている
  ▸ Artifact
やったこと理由
<details> で折りたたむ開閉の JS が要らず、キーボード操作もブラウザ任せにできる
見ているページの欄だけ開く直リンクやブックマークで来たとき、閉じていると現在地が分からない
OVERVIEW に出すものは PER PR から除く二重に出さない
見出しに区切り線灰色の小さな文字だとリンクの一種に見える
ファイル名を一段深く小見出しの下にあることを見た目で示す

JS を圧縮しない判断

README に「学習教材のため、JS は未圧縮・未難読化」と明記した。手抜きではなく、選んだこと。

生gzip 後
config.js1,977 B1,085 B
library.js5,730 B2,255 B
reader.js24,270 B8,320 B
合計32 KB11.7 KB

実際に流れるのは gzip 後の 11.7 KB で、Cloud CDN がキャッシュする。minify で削れるのは初回の 3〜4 KB。クライアント JS の難読化は保護にならない（開発者ツールで整形して読める）。ビルドツールを入れない方針とも矛盾する。そしてコメント付きの読めるソースが、このリポジトリでは資産。

CDN のキャッシュを消す。何もしなければ最大 5 分は古い版が見える。?cb=… はキャッシュキーに含まれないので回避にならない。

手元の index.json を消す。ビューアは index.json を優先するので、残すと新しい Markdown がローカルのサイドバーに出なくなる。

この手順は Step.11 で CD へ

main へのマージで自動で流れるようになる。

リポジトリを公開する

一度でも履歴に入った秘密情報は、あとから消しても残る。公開前に Git の履歴全体を走査した。

確認結果
.env履歴に一度も無い。.env.example の APP_KEY= は空
*.tfstate履歴に無い
鍵・API キー無い（PRIVATE KEY / AIza / ya29. / AKIA を全履歴で検索）
DB パスワード平文の混入なし。本番は Secret Manager

テストアカウントは意図して公開

本番の管理画面に実際に入れる資格情報。触ってもらう価値を取った。ログイン試行は 5 回でレート制限が掛かる。

プロジェクト ID やバケット名は問題ない

tfstate は非公開、Cloud SQL は IP 許可リストが空、Cloud Run は LB 経由のみ。アクセス制御を IAM に寄せてあるので、名前を知られても入口が無い。

ハマりどころ

症状原因
README の表が表にならない区切り線の上にヘッダ行が無い
<sub> の中の文字が重なるインライン要素の中にリスト（ブロック要素）を入れた
注意書きの 2 項目が 1 行につながる> の行は同じ段落に結合される。- の箇条書きにする
本番の docs に新しいページが出ないCloud CDN が古い index.json を返している
ローカルで新しい md が出ないデプロイで作った index.json が残っている

GitHub の Markdown で複数行を確実に小さくする手段は実質無い。<small> や style はサニタイザで落ちる。README の注意書きは alert 記法（> [!NOTE]）で本文から一段引いた。
