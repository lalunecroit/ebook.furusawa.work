API と CDN の分離ノート

ベタ書きだったページ一覧を API に移し、画像は API を通さず CDN から直接配る。その線の引き方と、キャッシュの効かせ方。

4つのコンテナ

Step.01 の frontend / docs に、画像を配る cdn と JSON を返す backend が加わった。

サービスポート中身役割
frontend8080nginx:1.27-alpineビューア本体。HTML / CSS / JS のみ
backend8000php:8.4-cli-alpine書誌情報とページ一覧を JSON で返す
cdn8082nginx:1.27-alpineページ画像。動的処理は一切しない
docs8081nginx:1.27-alpineこのドキュメント

backend だけ build、残り3つは公式イメージをそのまま使っている。cdn と docs は「公開ディレクトリと設定ファイルをマウントするだけ」で同じ形をしている。

Step.01 から引き継いだ約束

公開するのは public/ ひとつだけ、マウントも public/ ひとつだけ（サブディレクトリを個別にマウントすると Docker Desktop 側でマウントが外れる）。nginx.conf は public/ の外。sendfile off。cdn も同じ規則に従っている。

画像を API に通さない

API が返すのは画像の URL だけ。バイト列は CDN からブラウザへ直接流れる。

ブラウザreader.js
▶
API :8000total_pages と URL 10個 (JSON 約2KB)
ブラウザ<img src>
▶
CDN :8082page-01.svg … (画像本体)

この線を引いておくと、PHP のプロセス数がページ表示のボトルネックにならない。読者が10ページめくっても API へのリクエストは起動時の1回だけで、あとは静的ファイル配信だけが走る。

将来 CDN を実サービス（CloudFront / Cloud CDN など）に差し替えるときも、変わるのは CDN_BASE_URL の値だけで、フロントも API のロジックも触らずに済む。

ベース URL はブラウザ基準で渡す

compose.yaml では CDN_BASE_URL: "http://localhost:8082" を渡している。Docker のネットワーク内なら http://cdn で届くが、この URL を実際に叩くのは PHP ではなくブラウザなので、コンテナ名を入れると解決できない。API が組み立てた URL が誰の名前解決を通るのかで決まる。

API の形

エンドポイントは2本。ビューアは1本目だけで起動できる。

メソッドパス返すもの
GET/api/books/{slug}書誌情報 + ページ一覧
GET/api/books/{slug}/pagesページ一覧のみ
 
{
  "data": {
    "slug":         "sample",
    "title":        "Docker で作る電子書籍サービス",
    "published_at": "2026-09-20",
    "total_pages":  10,
    "pages": [
      {
        "page_no":    1,
        "img_path":   "/books/sample/page-01.svg",        ← DB に入れる値
        "updated_at": "2026-09-20T20:00:00+00:00",
        "url":        "http://localhost:8082/books/sample/page-01.svg?v=1758398400"
      }                                                       ↑ ブラウザが使う完成形
    ]
  }
}

img_path と url を両方返している。前者は CDN のドキュメントルートからの相対パス、後者はベース URL とキャッシュバスターを足した完成形。フロントが見るのは url だけで、img_path は将来の管理画面やデバッグのために残してある。

データはまだ PHP の定数

BookController::BOOKS にベタ書きしている。ただしキーの構造を将来のテーブルに合わせてあるので、DB を入れる段階では定数を Eloquent のクエリに差し替えるだけで、レスポンスの形は変わらない。

ベタ書き想定テーブル
配列のキー 'sample'books.slug
title / description / published_atbooks の各カラム
pages[].page_no / img_path / updated_atbooks_pages の各カラム
例外も JSON で返す

bootstrap/app.php で shouldRenderJsonWhen(fn ($request) => $request->is('api/*')) を設定してある。これが無いと、存在しない slug を叩いたときに Laravel の HTML エラーページが返り、フロント側の res.json() がパースエラーで落ちる。API の失敗は必ず JSON で返す。

キャッシュ戦略

このステップの主題。方針はひとつ——画像は1年キャッシュさせる。差し替えたら URL を変える。

ふたつの設定が組でひとつの仕組みになっている。片方だけでは成り立たない。

どこ何をする効果
CDN Cache-Control: public, max-age=31536000, immutable 一度読んだ画像は二度と取りに来ない
API ?v={updated_at の Unix time} を付けて返す 差し替えたページだけ URL が変わる

immutable が効く場面

max-age だけでも有効期限内なら再取得は起きないが、ユーザーがリロードすると条件付きリクエスト（If-Modified-Since）が飛ぶ。画像10枚なら 10 往復。immutable を付けるとブラウザはこの再検証もしなくなる。「中身は絶対に変わらない」と宣言しているので、確認する理由がない。

だから URL 側で回す

「絶対に変わらない」と言い切った以上、同じ URL のまま画像を差し替えても届かない。そこで books_pages.updated_at を ?v= に載せる。

// BookController::pageList()
$version = Carbon::parse($page['updated_at'])->getTimestamp();
'url' => $base.$page['img_path'].'?v='.$version,

API 自身はキャッシュさせていない（Cache-Control: no-cache）。だから新しい ?v= は次のリロードで確実に届く。「変わらないもの」を長く、「変わるもの」を短く——キャッシュの効かせ方はこの一行に尽きる。

Cache-Control を2行出さない

nginx の expires ディレクティブは Cache-Control を自分で出力する。add_header Cache-Control と併用するとヘッダが2行になり、どちらが採用されるかが環境依存になる。immutable は expires では書けないので、add_header 1行にまとめている。

CDN の nginx 設定

配るのはページ画像だけ。動的処理は一切しない、と決めた上での設定。

圧縮するもの / しないもの

gzip_types      image/svg+xml;   ← SVG はテキストなので効く
gzip_comp_level 6;
gzip_min_length 512;
gzip_static     on;              ← page-01.svg.gz があればそれを返す

PNG / JPEG / WebP / AVIF は対象に入れていない。 これらは既に圧縮済みで、gzip をかけてもほぼ縮まらず CPU を捨てるだけになる。「全部 gzip」は設定としては短いが、画像配信では素直に損をする。

gzip_static on は事前生成した .gz を優先する設定。今は .gz を置いていないので実行時圧縮だが、ページ枚数が増えたらビルド時に生成して切り替えられる。

配らないものを決める

location ~* \.(php|js|mjs|json|html?|conf|env|sh|py)$ {
    return 404;
}

画像しか置かない場所なので、それ以外の拡張子は拒否する。autoindex on でディレクトリを一覧できるようにしてあるぶん、置き間違えたファイルが見えてしまう事故を1枚挟んで防いでいる。autoindex は開発時の確認用なので、本番では外す。

その他

設定理由
open_file_cache同じファイルを繰り返し配るので、メタ情報をキャッシュして stat の回数を減らす
sendfile offDocker Desktop の仮想 FS と相性が悪く、差し替え後に古い内容が配信される（Step.01 の frontend と同じ）
access_log off画像は本数が多く、ログが実質ノイズになる
Access-Control-Allow-Origin: *将来 fetch や canvas で画像を扱う場合に備えて

フロントの接続

CONFIG から固定値が消えた。それ以外はほとんど変わっていない。

// Step.01
totalPages: 10,
pageSrc: (n) => `assets/pages/page-${String(n).padStart(2,'0')}.svg`,

// Step.02
api: { base: 'http://localhost:8000/api', slug: 'sample' },
totalPages: 0,                         // API の total_pages で上書き
pageSrc: (n) => pageUrls.get(n) ?? '',   // 中身は API レスポンス
呼び出し側は1行も変わっていない

pageSrc のシグネチャ（ページ番号 → URL の文字列）を保ったので、goTo() / preloadAround() / render() は無変更。Step.01 で画像URLの決定を1箇所に閉じ込めておいたことが、そのまま差し替え可能性になっている。pageUrls を Map にしたのも、将来ページを分割取得する（全部揃う前に先頭だけ表示する）余地を残すため。

CORS は設定していない

:8080 から :8000 への fetch はクロスオリジンだが、Laravel 11 以降は HandleCors がグローバルミドルウェアに最初から入っている。フレームワーク既定の設定が paths: ['api/*'] / allowed_origins: ['*'] なので、config/cors.php を置かなくても /api/* は通る。

認証を入れて Cookie を使う段階になったら php artisan config:publish cors で設定ファイルを出し、supports_credentials を有効にした上でオリジンを * から実際のドメインに絞る必要がある（この2つは併用できない）。

起動に失敗したとき

ページ一覧が無ければビューアは成立しない。中途半端に起動させない。

async function init() {
  document.documentElement.style.setProperty('--flip-duration', `${CONFIG.animationMs}ms`);

  el.spinner.hidden = false;
  try {
    const book = await fetchBook();        // これが無いと何も表示できない
    if (book.title) {
      el.bookTitle.textContent = book.title;
      document.title = book.title;
    }
  } catch (e) {
    showFatal(`書誌情報を取得できませんでした: ${e.message}`);
    return;                              // bindEvents() を呼ばずに抜ける
  }
  el.spinner.hidden = true;

  // ... 以降は Step.01 のまま
}

bindEvents() の手前で return しているのがポイント。操作だけ効いて絵が出ない、という状態を作らない。 空の <img> をめくり続けられるより、理由が書いてある方が調べやすい。

メッセージは .fatal の表示に加えて #liveRegion（aria-live="polite"）にも流し、console.error にも出している。読み上げ環境でも、DevTools を開いている人にも失敗が伝わる。

スピナーは必ず消す

showFatal() の先頭で el.spinner.hidden = true にしている。ここを忘れると、エラーメッセージの上でスピナーが回り続けるという最悪の画面になる。「読み込み中」と「失敗」は排他。

ハマりどころ

症状原因
画像だけ表示されない CDN_BASE_URL がコンテナ名 (http://cdn) になっている。この URL を叩くのはブラウザなので、ホストから見えるアドレスが要る（→ §02）
画像を差し替えても反映されない immutable が効いている。これは想定どおりの動作。 updated_at を更新して ?v= を回す（→ §04）
逆に毎回取りに来てしまう updated_at を now() のような動的な値にしている。?v= はリクエストごとに変わってはいけない
Cache-Control が2行返る expires と add_header Cache-Control の併用（→ §04）
fetch が CORS で弾かれる パスが /api/ 配下から外れている。既定の CORS 設定は paths: ['api/*'] にしか効かない
404 のときにフロントが JSON パースエラーで落ちる shouldRenderJsonWhen が外れて HTML エラーページが返っている（→ §03）
total_pages と実際の画像枚数がずれる BOOKS の pages 配列と cdn/public/books/{slug}/ の中身は別管理。total_pages は配列の count() なので、配列に足して画像を置き忘れると 404 の <img> になる
backend コンテナが起動しない ./backend:/app を bind mount しているので vendor/ はホスト側のものが使われる。ホストで composer install が済んでいる必要がある

積み残し

動いてはいるが、次に触るときに片付けるもの。

  • frontend/public/assets/pages/*.svg が参照されないまま残っている。画像は cdn/public/ に複製する形で追加したため、フロント側の10枚は現在デッドファイル
  • backend/ に laravel new の雛形がそのまま入っている（User モデル、welcome.blade.php、vite.config.js、Laravel の README.md）。API しか使わないので整理の余地がある
  • artisan serve はシングルプロセスの開発用サーバ。本番構成では php-fpm + nginx（または Octane）に差し替える
  • 書籍データが PHP の定数。BOOKS を Eloquent に置き換えるのが次の作業
