このステップで増えたコンテナは無い。変わったのは backend の役割で、これまで「公開 API を返すだけ」だったところに /admin/* が加わり、cdn への書き込みも行うようになった (cdn/public/ を両方のコンテナにマウントしている)。

読者と管理者が同じ :8000 を共有している点は、本番でサブドメインを分ける段階 (api. / admin.) で見直す予定。

管理画面の入口

画面は backend に Blade で作った。フォーム送信・CSRF・バリデーションエラーの差し戻しを Laravel に任せられ、管理画面の一式を backend の中に閉じ込められる。

// bootstrap/app.php
->withRouting(
    ...
    then: function (): void {
        Route::middleware('web')          ← セッションと CSRF
            ->prefix('admin')
            ->name('admin.')
            ->group(base_path('routes/admin.php'));
    },
)

ルートは web.php と分けて routes/admin.php に置いた。api 側とはミドルウェアが違うので、ファイルごと分けておくと混ざらない。

メソッドパス用途
GET/admin/books一覧（未公開も含む）
GET / POST/admin/books/create · /admin/books新規登録
GET / PUT/admin/books/{book}/edit · /admin/books/{book}編集
GET/admin/books/{book}/pagesページ画像の管理画面
POST/admin/books/{book}/pages画像のアップロード（追加・差し替え）

認証は §08 で入れた

当初は「上の then: に ->middleware('auth') を1行足すだけ」と考えていたが、ログイン画面自体は未ログインで開けなければならないので、そうはいかなかった。routes/admin.php の中で guest と auth に分けている。

書誌情報の登録・編集

コントローラは2行。SQL は Eloquent が組み立てる。

$book = Book::create($request->validated());   ← 登録
$book->update($request->validated());          ← 更新
-- 実際に発行された SQL
insert into `books` (`code`, `title`, `description`, `published_at`, `updated_at`, `created_at`) values (?, ?, ?, ?, ?, ?)
update `books` set `title` = ?, `books`.`updated_at` = ? where `id` = ?

UPDATE は変わった列だけになっている。Book モデルに書いたのは設定だけで、#[Fillable] が「リストに無いキーを黙って捨てる」ことで、フォームに is_active（生成列）を仕込まれても書き込まれない。

書籍コードの一意性はスキーマと同じ考え方で

'code' => [
    'required', 'string', 'max:64',
    'regex:/^[a-z0-9]+(?:-[a-z0-9]+)*$/',
    Rule::unique('books', 'code')
        ->whereNull('deleted_at')    ← 削除済みとは重複してよい
        ->ignore($book),             ← 編集中の自分自身は除く
],

Step.03 で (code, is_active) の複合ユニークとして表現した約束を、フォームのバリデーションにも書いた。DB の制約だけに頼ると重複時に 500 になる。先に弾いて、入力を保ったまま差し戻すため。

画像がまだ無い書籍

書誌情報だけ先に登録できるようになり、ページが0枚の書籍が公開側に出てくるようになった。API はすべて 200 で応答するが、画面が2か所崩れた。

一覧: 表紙が無いとカードの高さが崩れる

img.src = book.cover?.url ?? CONFIG.noImagePath;   ← 'assets/no-image.svg'

ページ画像と同じ 800×1131 の「No Image」SVG を置いた。aspect-ratio: 800 / 1131 の枠に収まるので、全カードの高さがそろう（実測で全件 517px）。

ビューア: 白紙のまま操作できない

totalPages = 0 で起動すると、画像は src=""、ナビは両方無効、終端モーダルも出ない。エラーも出ないので「ただ壊れている」ようにしか見えない。起動時に判定して案内を出すようにした。

if (CONFIG.totalPages === 0) {
  showEmpty();   ← 「この書籍にはまだページがありません。」+ 一覧へ戻るリンク
  return;
}
クラス用途色
.notice--fatalAPI 取得失敗（異常）赤系
.notice--noticeページ未登録（運用途中の正常な状態）グレー

どちらにも一覧へ戻るリンクを付けた。Step.05 の最終ページと同じく、行き止まりに導線を置かない。

ページ画像のアップロード

画像の実体は cdn サービスが配信している cdn/public/ に書く。backend は自分のディレクトリしか見えていなかったので、マウントを渡した。

# compose.yaml (backend)
volumes:
  - ./backend:/app
  - ./cdn/public:/var/www/cdn
// config/filesystems.php
'cdn' => [
    'driver' => 'local',
    'root' => env('CDN_ROOT', '/var/www/cdn'),
    'throw' => true,
],

file_put_contents() を直接書かず Storage を通すのは、本番で GCS に移すとき driver を差し替えるだけで済ませるため。

ページ番号を決める省略なら max + 1
▶
古いファイルを消す差し替えのとき
▶
保存 → DB 更新updateOrCreate + touch()

追加と差し替えは同じ POST にまとめ、page_no を送るかどうかで分けている。レスポンスは新規なら 201、差し替えなら 200。

パスの先頭スラッシュ

既存の img_path は /books/sample/page-01.svg と先頭スラッシュ付きで、公開 API はこれに CDN のベース URL を連結している。Storage のパスはルート相対なので、DB は先頭スラッシュ付き、ディスク操作のときだけ ltrim($path, '/') と役割を分けた。最初はスラッシュ無しで保存しかけており、そのままだと URL が http://localhost:8082books/… になるところだった。

保存したファイルの権限

最初の実装では、アップロードした画像が nginx から 403 になることがあった。Storage の local ドライバは既定で private として書き込むため、ディレクトリが 0700・ファイルが 0600 になり、書いた PHP と配信する nginx が別ユーザーだと読めない。

'visibility' => 'public',              ← ファイルを 0644 に
'directory_visibility' => 'public',    ← ディレクトリを 0755 に

「公開ディレクトリに置くのだから読めて当然」と考えたくなるが、書き込み側の既定は非公開。GCS に移す段階でも同じ話が出てくる（オブジェクトの公開設定）。

削除は所有者を確認する

abort_if($page->book_id !== $book->id, 404);

{page} は ID で引かれるので、URL の書籍部分を差し替えると別の書籍のページを消せてしまう。組み合わせが合わなければ 404。

touch() がこの機能の要

同じ拡張子で差し替えると img_path は変わらない。Eloquent は「変更なし」と判断して UPDATE を発行せず、updated_at も動かない。

$page = $book->pages()->updateOrCreate(['page_no' => $pageNo], ['img_path' => $path]);
$page->touch();   ← これが無いと差し替えが読者に届かない

画像 URL のキャッシュバスターは ?v=<updated_at> で、CDN は Step.02 から「1年 + immutable」でキャッシュさせている。touch() が無いと URL が変わらず、ブラウザは古い画像を持ち続ける。

画像 URL
差し替え前…/page-01.png?v=1790052491
touch() なし…/page-01.png?v=1790052491（同じ。届かない）
touch() あり…/page-01.png?v=1790052503（変わる。取り直される）
書く経路が増えたら、約束も持ち込む

Step.02 のキャッシュ戦略、Step.03 の ON UPDATE CURRENT_TIMESTAMP と同じ約束を、管理画面の書き込み経路でも守っている。読む側だけで成り立っていた前提は、書く経路が増えるたびに確認し直す必要がある。

拡張子が変わる差し替え（PNG → JPEG など）ではファイル名も変わるので、保存前に古いファイルを消している。放置すると page-01.png と page-01.jpg が両方残る。

ドラッグ&ドロップ

上部の大きな領域に落とすと末尾に追加、各ページのサムネイルに落とすとそのページを差し替え。1枚ずつ受け付ける。

node.addEventListener('dragover', (ev) => {
  ev.preventDefault();    ← これが無いと drop が発火せず、ブラウザが画像を開く
  node.classList.add('is-over');
});
const body = new FormData();
body.append('image', file);
if (pageNo) body.append('page_no', pageNo);

await fetch(uploadUrl, {
  method: 'POST',
  headers: { 'X-CSRF-TOKEN': token, Accept: 'application/json' },
  body,
});

Content-Type はあえて指定していない。FormData を渡すとブラウザが multipart/form-data の境界文字列ごと組み立てるので、手で書くと境界が欠けて壊れる。

Accept: application/json を付けているので、検証に失敗すると Laravel はリダイレクトではなく 422 + JSON を返し、画面はそのメッセージを表示する。mimes はファイル名ではなく中身から判定した MIME で検査し、保存時の拡張子も中身から推定したものを使う。アップロード時のファイル名は信用しない。

GD とテスト

backend にも GD を入れた。イメージは +10MB（実測）で、管理画面用に別イメージを作る管理コストの方が大きい。

テストでも効いた。UploadedFile::fake()->image() は GD で本物の画像を生成するので、MIME 判定まで実際のバイト列で検証できる。GD が無い間はダミーファイルで代用していた。

protected function setUp(): void
{
    parent::setUp();
    Storage::fake('cdn');   ← 実際の cdn/public/ を汚さない
}
$first = ...->json('page.url');
$this->travel(2)->seconds();   ← updated_at は秒単位。同じ秒だと URL が一致する
$second = ...->json('page.url');
$this->assertNotSame($first, $second);

書いたテストが回帰を捕まえるかも、わざと実装を壊して確かめた。BookRequest から ->whereNull('deleted_at') を消すと「削除済みの書籍とはコードが重複してよい」が、管理画面の一覧に published() を付けると「一覧には未公開と公開予約も出る」が、それぞれ落ちる。

ログイン認証

誰でも開けた /admin に鍵をかける。Laravel 標準のセッション認証（web ガード + 既存の users テーブル）。Breeze は Vite / npm を持ち込むので使わず、必要な分だけ自前で書いた。

auth はグループ全体ではなく機能ごとに付ける

// 未ログイン専用
Route::middleware('guest')->group(function (): void {
    Route::get('/login', [AuthController::class, 'create'])->name('login');
    Route::post('/login', [AuthController::class, 'store'])->name('login.store');
});

// ここから下はログインが必要
Route::middleware('auth')->group(function (): void {
    Route::post('/logout', [AuthController::class, 'destroy'])->name('logout');
    ...
});

行き先は bootstrap/app.php で固定した。セッション認証を使うのは管理画面だけなので迷う余地がない。

$middleware->redirectGuestsTo(fn () => route('admin.login'));
$middleware->redirectUsersTo(fn () => route('admin.books.index'));

入れた安全策

対策内容
ログイン試行の制限メールアドレス + IP 単位で5回失敗するとロック。ロック中は正しいパスワードでも入れない
エラー文言を区別しない「パスワード違い」も「存在しないメールアドレス」も同じ文言
セッション固定攻撃の対策ログイン時に session()->regenerate() で ID を作り直す
ログアウトは POST のみGET だと <img src="/admin/logout"> で他サイトから強制ログアウトさせられる
intended リダイレクトログイン後、開こうとしていたページに戻る
失敗の理由を教えない

「このメールアドレスは登録されていません」と返すと、登録済みのアドレスを総当たりで特定できてしまう。どちらが違っても同じ文言にする。

管理者は artisan コマンドで作る

docker compose exec backend php artisan admin:user admin@example.com --name=管理者
# → パスワードを対話式で入力（8文字以上）

登録画面は用意しない（誰でも管理者になれてしまう）。パスワードを引数で受け取らないのは、シェルの履歴に残るため。User の casts() で password => 'hashed' になっているので、コマンド側でハッシュ化は書いていない。

ハマりどころと積み残し

症状原因
差し替えても読者に古い画像が出る同じパスへの上書きでは updated_at が動かない。touch() で進める
差し替えで古いファイルが残る拡張子が変わるとファイル名も変わる。保存前に消す
URL が …8082books/… になるDB は先頭スラッシュ付き、Storage はルート相対。境界で変換する

積み残し

  • users テーブルの全員が管理者。読者向けのアカウントを作る段階では、権限の列か別ガードが要る
  • ファイル保存と DB 更新が非原子的。途中で失敗すると画像が失われうる。新ファイルを別名で保存し、DB 確定後に古いファイルを消す順序が定石
  • 同時アップロードの競合。2人が同時に末尾へ追加すると同じ max + 1 を計算し、片方が一意制約違反になる。lockForUpdate() 付きのトランザクションで番号を採る
  • ページ番号の振り直しが無い（途中を削除すると番号が飛ぶ）
  • SVG を受け入れている。スクリプトを埋め込める形式なので、不特定多数が使う運用の前に見直す
  • バリデーションメッセージが英日混在
