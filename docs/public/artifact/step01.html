全体の考え方

状態を1か所に集め、画面はその写像として作る。これだけ守れば改造しても壊れにくい。

入力ボタン / キー / スワイプ / シークバー
▶
statecurrent / direction / isFlipping
▶
render()state を見て UI を合わせる
▶
DOMページ番号・シークバー・ナビ

入力ハンドラは state を書き換えて render() を呼ぶだけ。DOM を直接いじる処理を render() に集約してあるので、「どこで画面が変わるのか」を探す範囲が一箇所で済む。

例外はひとつ

ページ画像の差し替えだけは goTo() が直接行う。アニメーションの途中で <img> の src を差し替えるタイミングが、描画の都合と強く結びついているため。逆に言うと DOM を直接触っているのは render() と goTo() / finishFlip() だけ。

状態は3つしか持っていない。派生値（「次のページはあるか」など）は都度計算する方針にしてあるので、状態の同期ズレが起きない。

// 「今の画面を復元するのに必要な最小限」だけを置く
const state = {
  current:    1,      // 現在ページ (1 始まり)
  direction:  'ltr',  // 綴じ方向。実行中に切り替えられる
  isFlipping: false,  // めくり中は操作を受け付けない
};

ファイル構成

バックエンドを足すときは backend/ を並べ、compose.yaml にサービスを追加する想定。

公開されるのは frontend/public/ 配下だけ。Dockerfile や nginx.conf・tools/ は その外に置いてあるので、Web からは見えない。

アニメーションの実体は CSS にあるという点が重要。JavaScript がやっているのは「回転角の数値を入れ替える」ことだけで、その間を補間しているのは CSS の transition。JS 側でコマ送りしているわけではないので、requestAnimationFrame ループは存在しない。

レイヤ構造

重なっている <img> は2枚だけ。10ページあっても DOM は増えない。

.book                     ← ページ1枚分の矩形 (aspect-ratio で比率固定)
├─ #pageUnder             ← 下地。常に表示されている
└─ #sheet                 ← 回転する「紙」。これだけが動く
   ├─ #pageFlip           ← 紙の表面に貼る画像
   └─ #sheetShade         ← めくり中に濃くなる影

静止しているときは2枚とも同じページ

ここが地味だが効いている設計。下地と紙に同じ絵を表示しておくと、めくり終わりに紙の角度を 180deg から 0deg へ戻す瞬間にも、下にすでに正しい絵があるのでチラつきが起きない。

「紙を隠す → 絵を差し替える → 紙を出す」といった順序制御や、画像のデコード完了待ちが一切不要になる。

キーとなる CSS

backface-visibility: hidden ── 紙が90度を超えると裏返しになり、自動的に見えなくなる。「いつ紙を消すか」を JS で判定する必要がない。

transform-origin ── 回転の軸。これを綴じ目（左綴じなら左端）に置くことで、本の背表紙を軸に回る動きになる。中央のままだと紙が空中で回転してしまう。

perspective: 2400px ── .stage 側に指定。これが無いと rotateY は単なる横方向の縮小に見える。

めくりの原理

綴じ目を軸に紙を 0deg → -180deg まで倒す。90度を境に紙が消え、下地が現れる。

進む / 戻るは同じ仕組みの裏返し

「紙に貼る絵」と「回転の開始・終了角」を入れ替えるだけで、戻る動きになる。分岐はこの2点しかない。

下地 #pageUnder紙 #pageFlip開始角終了角
進む 遷移先を敷く 現在ページ（そのまま） 0deg -180deg
戻る 現在ページ（そのまま） 遷移先を貼る -180deg 0deg

戻るときは、紙が -180deg（＝裏返しで不可視）の状態から起き上がってくる。90度を切ったところで表面が現れ、下地の現在ページに覆いかぶさる ── 実際に前のページをめくり戻す動きになる。

goTo() の手順

ページ遷移はすべてこの関数を通る。手順は4つで、順番に意味がある。

  1. 絵を決める

    進むなら下地に遷移先を、戻るなら紙に遷移先を貼る。showSpinnerUntilLoaded() で、まだ読み込めていない場合だけスピナーを出す。

  2. transition を切って開始角に置く

    .is-animating クラスを外した状態で transform を設定する。このクラスが transition を持っているので、外れている間の変更は瞬時に反映される。

  3. リフローで確定させる

    forceReflow() を呼ぶ。これが無いとアニメーションが再生されない（→ §06）。

  4. transition を入れて終了角へ

    .is-animating を付けてから transform を書き換える。あとは CSS が補間する。animationMs 後に finishFlip() が走り、紙を 0deg に戻して両レイヤを遷移先に揃える。

// ② transition を切った状態で開始角度に置く
el.sheet.classList.remove('is-animating');
el.sheet.style.transformOrigin = spineOrigin();
setSheetAngle(forward ? 0 : angle);

forceReflow(el.sheet);   // ③ ここまでを確定させる

// ④ transition を入れて終了角度へ
el.sheet.classList.add('is-animating');
setSheetAngle(forward ? angle : 0);
transitionend ではなく setTimeout

後始末は transitionend ではなく setTimeout で予約している。タブが裏に回るなどで transitionend が発火しないことがあり、そうなると isFlipping が true のまま固まってビューアが操作不能になるため。タイマーなら必ず終わる。

リフローが要る理由

CSS transition の再生でいちばん踏みやすい落とし穴。

ブラウザはスタイルの変更をすぐには反映せず、同じフレーム内の変更をまとめてから適用する。そのため、以下のように書くと 開始角が無かったことにされる。

// ✗ アニメーションしない
sheet.style.transform = 'rotateY(-180deg)';  // 開始角
sheet.classList.add('is-animating');
sheet.style.transform = 'rotateY(0deg)';     // 終了角
// → ブラウザには「0deg のまま何も変わらなかった」としか見えない

間に一度レイアウト計算を強制すると、開始角がスタイルとして確定し、そこからの変化として transition が再生される。offsetWidth の読み取りがそれを引き起こす。

// ○ 読み取りがレイアウトを強制的に確定させる
function forceReflow(node) {
  void node.offsetWidth;
}

void を付けているのは「値は使わない、副作用だけが目的」だと明示するため。これが無いと単なる未使用の式に見え、Linter や将来の自分に消されかねない。

綴じ方向の切り替え

左綴じ（横書き）と右綴じ（縦書き・マンガ）を実行中に切り替える。分岐は3つの関数に閉じ込めてある。

関数ltr（左綴じ）rtl（右綴じ）効果
spineOrigin()left centerright center回転軸の位置
flipAngle()-180180倒れる向き
deltaForSide()右＝次へ左＝次へタップ／矢印キーの対応

影のグラデーションの向きだけは CSS 側で持っている。render() が <div id="reader"> に data-direction を書き込み、[data-direction="rtl"] のルールで反転させる。

分岐を増やしたくなったら

「左綴じのときだけ〜」という if をハンドラ側に書き足すのではなく、この3関数のどれかを拡張する。分岐が散らばると、綴じ方向を切り替えたときだけ挙動がおかしい、という追いにくいバグになる。

入力ハンドリング

すべての入力は最終的に move(delta) か goTo(page) に合流する。

操作動作備考
画面左右のタップ前 / 次綴じ方向で入れ替わる
← →前 / 次綴じ方向で入れ替わる
PageUp PageDown前 / 次綴じ方向によらず固定
Space次（Shiftで前）
Home End最初 / 最後
F全画面
横スワイプ前 / 次50px 以上かつ縦移動より大きいときのみ
シークバー任意のページへドラッグ中は animate: false で即時表示

スワイプは touchstart ではなく Pointer Events を使っている。マウス・タッチ・ペンを同じコードで扱えるため。.stage には touch-action: pan-y を指定し、横方向のジェスチャだけを JS に回している。

誤爆を防いでいる2つの条件

Math.abs(dx) < threshold で小さな指ブレを無視し、Math.abs(dx) < Math.abs(dy) で縦スクロール目的の動きを除外している。片方だけだと、縦に払っただけでページがめくれる。

改造レシピ

よくやる変更と、触るべき場所。

めくる速さを変える

CONFIG.animationMs だけ変えればよい。起動時に init() が CSS 変数 --flip-duration を上書きするので、CSS 側を直す必要はない。

// frontend/public/js/reader.js
animationMs: 400,   // 既定 600

ページ数・画像を差し替える

totalPages と pageSrc の2つ。JPEG にしても拡張子を変えるだけで済む。

totalPages: 240,
pageSrc: (n) => `assets/pages/page-${String(n).padStart(3, '0')}.jpg`,

バックエンドから取得する

pageSrc を API のパスに向け、init() の冒頭で書誌情報を取って CONFIG を上書きする。totalPages が確定してから render() を呼ぶ順序だけ守ればよい。

async function init() {
  const book = await fetch('/api/books/001').then(r => r.json());
  CONFIG.totalPages = book.pageCount;
  CONFIG.pageSrc = (n) => `/api/books/001/pages/${n}`;
  CONFIG.direction = book.direction;
  // ... 以降は現状のまま
}

見開き表示にする

いちばん大きい改造。state.current を「左ページ番号」と読み替え、move() の増分を 2 にし、.book の aspect-ratio を倍にして <img> を左右2枚ずつ持つ。レイヤの2枚構造と回転の仕組みはそのまま使える ── 紙が片側だけになる分、transform-origin は常に見開きの中央になる。

しおりをサーバに保存する

saveProgress() / loadProgress() の中身を差し替えるだけ。呼び出し側（afterPageChange() と init()）は触らない。保存は連打されるので、送信前に debounce を挟むこと。

コンソールから動かして試す

デバッグ用に window.reader を生やしてある。ブラウザの DevTools からそのまま叩ける。

reader.goTo(5);                // 5ページへ
reader.state;                   // 現在の状態
reader.CONFIG.animationMs = 0;  // めくりを即時に

ハマりどころ

壊したときに真っ先に疑う場所。

症状原因
めくりの途中で絵が切り替わる CONFIG.animationMs と CSS の --flip-duration がずれている。init() が同期しているので、CSS を直接書き換えると逆にずれる
アニメーションせず瞬間移動する forceReflow() が抜けているか、.is-animating を付ける順序が逆（→ §06）
連打すると表示が壊れる isFlipping のガードを通らない経路を足した。新しい遷移は必ず goTo() 経由にする
紙が空中で回る transform-origin が中央のまま。render() と goTo() の両方で設定している
横に潰れるだけで立体に見えない .stage の perspective が効いていない。親子関係を変えたときに外れやすい
めくった瞬間に白紙が見える プリロードが届いていない。preloadRange を広げるか、画像を軽くする
CSS/JS だけ 404 になる bind mount が外れて、コンテナ内のディレクトリが空になっている。docker compose exec frontend ls /usr/share/nginx/html で確認。サブディレクトリを個別にマウントすると起きやすいので、公開ディレクトリ public/ を1つだけマウントしている
編集しても古い内容が配信される Docker Desktop の仮想 FS と nginx の sendfile の相性。nginx.conf の server ブロックで sendfile off にしてある（http 側に書くとベース設定と重複してエラーになる）
シークレットウィンドウで落ちる localStorage が例外を投げる。読み書きは必ず try/catch で包む
アクセシビリティも維持する

prefers-reduced-motion: reduce のとき、CSS 側で --flip-duration を 1ms にして即時切り替えにしている。アニメーション周りを触るときはこの指定を消さないこと。ページ番号の読み上げは #liveRegion（aria-live="polite"）が担当している。
