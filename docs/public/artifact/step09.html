そもそも本番に Test User を作られては困る。Faker が無くて偶然止まったが、止まるべき理由はそこではない。テストユーザは開発とテストのときだけにし、書籍は環境を問わず入れる。

if (app()->environment('local', 'testing')
    && ! User::where('email', 'test@example.com')->exists()) {

$this->call(BookSeeder::class);

存在チェックも足して冪等にした。元の形では 2 回目の db:seed が一意制約で落ちていた。BookSeeder は updateOrCreate で何度流しても同じになるので、それに揃えた。

admin ホストの / を管理画面へ

admin.ebook.furusawa.work/ が Laravel の初期画面を出していた。

// routes/web.php — welcome より前に置く
if ($adminHost = config('app.admin_host')) {
    Route::domain($adminHost)->group(function () {
        Route::redirect('/', '/admin/books');
    });
}

Route::get('/', fn () => view('welcome'));

管理画面グループではなく web.php に置く

welcome の / はホストを限定していないので全ホストに当たり、しかも管理画面を登録する then: より先に読まれる。あとから足した domain 付きの / は届かない。

redirect は group の中で

Route::domain(…)->redirect(…) とは書けない。redirect は RouteRegistrar の passthru に無い。

開発では生えない

ADMIN_HOST が空なので、localhost:8000/ は従来どおり welcome。README の手順で Laravel の起動確認に使っている。

開発環境は起動時にマイグレーション

セッションを DB に置いたので（Step.07）、sessions テーブルが無いと最初のリクエストから 500 になる。clone して up しただけの状態がこれ。

# backend/docker-entrypoint.sh（開発用）
php artisan migrate --force   # 適用済みなら何もしない
本番では流さない

Cloud Run はインスタンスが同時に複数立ち、起動のたびに流すと競合する。本番は Cloud Run Jobs（ebook-migrate）で単発に実行する。

本番への反映と確認

CI/CD はまだ無いので、手でイメージを作って差し替えた。この手順が Step.11 でそのまま CD になる。

build--platform linux/amd64
▶
pushapi:v2
▶
gcloud run … updateapi / admin / migrate

v1 を上書きせず v2 にする。上書きするとロールバック先が消える。Terraform ではなく gcloud で差し替えるのは、イメージを ignore_changes で Terraform の管理から外してあるため。
